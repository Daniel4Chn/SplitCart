# Receipt image processing specification

Requirements: IMG-01..08. Supports P-01..03, P-09, N-02..04, N-07.

## Boundary and validation

IMG-01: Accept a single JPEG/PNG upload, not a URL. Verify signature and actual decoded format; reject MIME mismatch, empty, truncated, oversized, animated/multiframe, and unsupported files. Apply byte limits while streaming and pixel/dimension limits before allocating full image buffers where the decoder permits. Untrusted decoding runs under host memory/CPU bounds. Filenames are ignored for storage; keys are generated internally. No PDF, HEIC, SVG, GIF, or archive decoding.

IMG-02: SHA-256 original bytes for owner-scoped duplicate detection. A byte-identical retry returns an existing receipt reference (409) and offers reopening it; do not create another charge. Recompressed/cropped versions are not guaranteed detectable. Identical bytes owned by another user disclose nothing.

IMG-03: Preserve private original, generate display derivative with EXIF removed and orientation applied. Temporary files use per-attempt private directories and are removed on success, failure, timeout, or abandoned-attempt sweep.

## Preprocessing and OCR

IMG-04: Normalize orientation, grayscale, estimate skew, and apply bounded deskew when reliable. Compare a conservative baseline with one thresholded candidate, record which was selected and why. Do not blindly perspective-warp or crop away receipt content; low-confidence crop/skew leaves the image intact and warns. Perspective correction is deferred unless corpus results justify it. Preserve coordinate transform metadata for source overlays.

IMG-05: Tesseract CLI with pinned English language data and bounded candidate count produces TSV text, confidence, and bounding boxes. Low confidence is a review hint, never a calibrated probability. Blur/glare/crop/empty-output warnings offer retake or manual entry; do not assert that every bad image can be detected.

IMG-06: Node invokes Python executable with argv, shell disabled, fixed environment allowlist, timeout, bounded stdout/stderr, and process-group supervision including Tesseract. Python has no network or DB responsibilities. Enforce one-active-attempt host capacity and return OCR_BUSY with retry guidance; no invisible queue.

## Process contract v1

Input: CLI receives --input INTERNAL_PATH and --request INTERNAL_JSON_PATH. The request contains schemaVersion=1, attemptId (UUID), language='eng', and fixed preprocessing options; paths are generated by the server. stdout contains exactly one UTF-8 JSON object; diagnostic stderr excludes receipt contents.

Success exit 0:

```json
{"schemaVersion":1,"attemptId":"uuid","status":"ok","image":{"width":1200,"height":2400,"coordinateSpace":"normalized-display","transform":[1,0,0,0,1,0,0,0,1]},"tokens":[{"id":"t1","text":"MILK","confidence":88,"box":[10,20,80,25],"lineId":"l1"}],"lines":[{"id":"l1","text":"MILK 3.49","tokenIds":["t1"]}],"candidate":{"currency":"USD","merchant":null,"purchasedOn":null,"items":[],"subtotalCents":null,"totalCents":null,"adjustments":[],"unparsedLineIds":["l1"]},"warnings":[{"code":"REVIEW_REQUIRED","lineIds":["l1"]}],"engine":{"processorVersion":"version","tesseractVersion":"version","languageDataVersion":"version","candidate":"baseline"}}
```

Identity transform above is illustrative; actual dimensions, transforms, and token list must correspond to the processed image. Candidate item/adjustment shapes are defined in receipt-parsing.md. Confidence is an integer 0..100 or null for unavailable TSV confidence; normalize engine sentinel values to null.

Expected failure exit 2: {schemaVersion:1, attemptId, status:'error', error:{code:'IMAGE_UNREADABLE'|'OCR_FAILED', message:SAFE_MESSAGE}, warnings:[]}. Unexpected nonzero exit, invalid JSON, unsupported schema, mismatched attempt ID, excess output, or timeout is mapped by Node to structured processing failure. Reject unknown fields where they could change behavior. Candidate monetary values are validated decimal integer strings or null.

IMG-07: Receipt editing state and processing state are independent. Processing: idle → processing → succeeded|failed. A successful result is a candidate only; importing it is an explicit version-checked draft mutation. Save source attempt reference, user edits, and provenance separately. Retry uses a new attempt; delete/rerun cannot mutate finalized receipts.

IMG-08: Persist attempts with deadlines. Crash recovery marks expired running attempts failed and cleans private scratch directories. UI can poll receipt state after a lost response; show retry/manual entry and do not claim completion on a network timeout.

## Acceptance

A-IMG-1: Valid JPEG/PNG produces contract-valid output and source-linked rows; the original evidence remains available privately.
A-IMG-2: Malformed/large/multiframe input is rejected before OCR; traversal filenames cannot escape storage.
A-IMG-3: Simulated hangs, output overflow, engine absence, malformed JSON, and restart produce recoverable failures and no orphan descendants or permanent processing state.
A-IMG-4: Concurrent edits survive OCR completion and duplicate uploads cannot create duplicate image records.

## Implemented contract refinements (2026-10-17)

Internal request additionally requires `mode: validate|ocr` and `mime: image/jpeg|image/png`. Validation success is `{schemaVersion:1,attemptId,status:"validated",image}`. OCR engine metadata includes `parserVersion` and `selectionReason`; schemas reject unknown fields. Transform records OCR-to-normalized-display geometry; token boxes are mapped back to normalized display coordinates. Candidate selection uses higher mean token confidence, baseline on ties, as a heuristic rather than an accuracy claim. Bounded deskew requires at least five consistent near-horizontal lines and leaves uncertain images intact.

Receipt responses expose the latest result separately from `reviewSource`, the exact source attempt of the saved reviewed draft. Expected worker error results are schema/attempt validated; IMAGE_UNREADABLE maps to 422 and OCR_FAILED to 502. Invalid/mismatched error JSON maps to 502.

ADR-003 UX update: browser camera capture automatically invokes private image transfer, processing and unreviewed new-draft population. API review and exact reconciliation are unchanged. There is no user-facing file-picker/extract/import sequence. Manual receipt-free entry defines its total by the entered item costs; photo receipt reconciliation still uses the reviewed printed total.

Recovery UI refinement (M5): reopen may import a validated successful attempt automatically only when every draft field is untouched (no items, adjustments, assignments, merchant, date, total, payer, source or review edits). Imports remain version-checked. Edited drafts are preserved on retry; explicit replacement asks for confirmation. The worker input/output contract is unchanged. Household account display metadata is a web response only and is never passed into Python.
